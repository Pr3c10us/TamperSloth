# Visual guidance

`annotatePage` and `waitForUserAction` are core tools available on every run. The agent checks the request against the current site's URL/title and live content, and initiates visual guidance for site-related actions without requiring “guide me.” Unrelated questions, summaries, research, explicit text-only requests, and explicit requests for the agent to act itself retain their appropriate behavior.

Transient drawing and observer-start failures are retried up to two times with the same annotation ID and a fresh target lookup. Invalid/ambiguous selectors or access restrictions immediately request new evidence instead of repeatedly issuing the same invalid call. If retries fail, the tool returns current DOM/screenshot evidence for re-anchoring the guide. The model retries with a verified new selector or measured region and keeps the unfinished step active; it does not immediately fall back to text-only instructions. Cancellation stops retries.

`annotatePage` supports arrows, highlights, rectangles, ellipses, corner brackets, freehand paths, and labels. Use a unique observed CSS selector to follow page layout and scrolling, or supply viewport CSS coordinates in `box` / `points`. All guide shapes use the app's lime accent (`#a8bd85`); legacy color arguments are accepted but do not alter the accent. Dashed strokes, line widths, stable IDs, and optional expiration support layered instructions. Remove individual marks by ID or clear the layer. Descriptions are rendered as text, never HTML. The layer uses an isolated closed shadow root. Drawings and tips do not intercept input; a separate temporary guard pauses site input only during guide drawing. There is a limit of 30 simultaneous annotations and 500 path points.

Shapes have a hand-drawn treatment: subtly irregular curved strokes with round joins, sketch ellipses and arrows, and light clipped diagonal hatching for highlights. Randomness is seeded by annotation ID, keeping the same sketch stable through rendering and scrolling. Target positions and arrow endpoints remain accurate; roughness affects stroke control points. Layout changes move the live stroke and cursor together, and the drawing hotspot is not clamped at viewport edges. The treatment uses native SVG paths without a drawing-library dependency.

Dashed edges are drawn as separate curved pencil strokes with varied lengths, gaps, and slight endpoint offsets. Dashed ellipses use an irregular dash pattern along a sketch curve. Highlight hatching also uses curved strokes with uneven spacing, clipped to the closed outline. The preview includes **Dashed outline** and **Dashed highlight** buttons.

On-page tips should use 3–8 action-first words, with detailed explanations in chat. The renderer caps visible tips at 90 characters while preserving the full accessible label. Placement measures wrapped text, checks all marked targets, and favors areas clear of nearby controls and other guidance. Explicit positions are preferences; they cannot cover a marked target. Labels reposition on scroll, resize, and layout changes, and hide if no safe position exists.

Descriptions appear in a compact dark bubble using the extension's bundled Geist font, with text only and no logo. When there is no description, the bubble hides and only the cursor remains. Bubble width grows with the text, up to the wrapping limit, without reserving empty space. The cursor uses the supplied Vector (1).svg path unchanged, with a black fill and white border plus a brighter, wider lime glow. The path is scaled uniformly into the cursor and positioned with its rounded tip at the drawing hotspot. Waiting and feedback are shown in chat, with screen-reader announcements on the page; there is no on-page waiting popup.

The visible stroke is built incrementally from the same sampled points used to position the cursor. Geometry is sampled once while connected to the SVG; animation frames use cached points for both the ink and cursor, without repeated SVG geometry queries. A zero-progress first frame preserves the initial move command, so every later partial path remains valid and paints immediately. Live strokes bypass the group shadow filter until completion. Source outlines stay intact until a valid animation is ready. Each subpath is drawn in order, with pen-up travel between separate strokes; no masks or simultaneous corner reveals are used. Outlines use one pass so the cursor does not retrace a finished shape. Drawings are queued so one cursor draws one guide at a time, taking 1.1–4.5 seconds depending on path length. `annotatePage` returns after drawing finishes, with a timeout fallback that restores the complete outline for tabs that suspend animation frames. Cursor movement uses eased transitions and a visible directional tilt (up to approximately 18 degrees while drawing); the bubble stays upright. Descriptions stay hidden until drawing finishes, then reveal one character every 45ms with a blinking caret, and width and height follow the typed text. The complete instruction is announced once for screen readers. Ordinary browser actions retain their existing timings; typing focus cues do not animate or lock input. Reduced motion draws immediately and shows the full description without typing or rotation. Clearing/removing guides, cancelling steps, and ending runs cancel pending drawing frames and typing timers.

During guide drawing, a transparent input guard pauses pointer, wheel, and keyboard input to prevent premature actions. Escape cancels and releases it. Completion, removal, cancellation, panel closure, and a seven-second watchdog release the guard. The user-action timeout starts when drawing is ready. Event matching re-resolves the target selector on each event so framework updates replacing the original node do not break later observation.

Cursor descriptions stay below the pointer at a 34px vertical offset, with horizontal placement adjusted to avoid covering marked controls. They never flip above it. Near the viewport bottom the resting guidance cursor can move upward to make room; actual input positions are preserved. If no safe position exists, the bubble hides and the instruction remains in chat. After drawing, the cursor rests beside the target. Starting a wait draws its instruction atomically and clears old annotations; pass `annotationIds` to retain a deliberate canvas region or path. Retained drawings belong to that step and disappear immediately on its expected action. Use `pointerup` for drawing/dragging. Actions captured after a selector annotation appears but before its wait begins are recognized, so the user does not have to repeat the action. Successful completion removes the description without showing another completion tooltip.

For each walkthrough step:

1. Inspect the page and identify a unique selector.
2. Call `waitForUserAction` with one instruction, selector, and event (`click`, `change`, `input`, `submit`, or `focusin`). For form completion prefer `change` over `input`, which completes on the first keystroke. Field values are never collected.
3. Where success requires a resulting change, include `expectedSelector` and `expectedState` (`visible`, `absent`, or `checked`). `event:state` waits directly for that condition, including troubleshooting/loading tasks.
4. Inspect the returned status and the current DOM/screenshot before proceeding. A click is evidence of an action, not proof of a successful operation.
5. Clear annotations at the end.

For resumable steps, supply `completion: {selector, state}` with a real success condition (`visible`, `absent`, `checked`, `selected`, or `pressed`). It is inspected before resolving the action target, so an already-selected tool or already-visible confirmation skips a completed step even when its old button selector is gone. Avoid using mere button visibility as proof of completion. Completed guidance receipts retain instructions and completion conditions in the run's compacted task state.

When starting or polling an observer fails, or it reports a lost context/timeout, the tool returns `needsReview` with a fresh accessibility snapshot, screenshot when available, and current page metadata. The agent compares this evidence against completed steps and resumes visual guidance at the first unfinished step with fresh selectors. It does not assume annotations are unsupported because a wait failed. Canvas progress requires screenshot inspection. Explicit cancellation is respected and does not trigger recovery. Recovery instructions limit attempts without new evidence to two before asking the user how to proceed.

Recovery includes `observationPhase` and `actionObserved` (true, false, or null when unknown). Chat labels distinguish an observer that could not start, an interrupted check, no detected action, and a detected action whose outcome is unconfirmed. Recovery does not imply user progress. If no action is detected, guidance stays on the current step rather than asking whether a later task is complete.

Only trusted user events satisfy action steps. Keyboard activation produces ordinary trusted click/change events. Wrong clicks increment a bounded counter without storing their targets or text and show a reminder. Escape cancels without preventing the page's own keyboard handling. Chat Stop sends cancellation too. Timeout defaults to 60 seconds, with a maximum of 120 seconds; results distinguish missing actions from missing resulting changes. The tool has a separate deadline in case page timers stop advancing. Polling uses short messages rather than keeping a service-worker request pending for the entire wait.

Navigation destroys the observation context and returns `lost`; re-inspect the new page rather than assuming the original action succeeded. Replacing a step cancels its listeners and timers. Guidance selectors support the main document and open shadow roots; closed roots and cross-origin frame targets need separate page inspection and cannot currently be anchored by this guidance API. Restricted Chrome pages return an error rather than a successful annotation.

Trusted CDP mouse, keyboard, text, touch, and drag events update the branded cursor before input is dispatched. Once shown, the cursor stays visible at its last position during pauses within a run. Run completion, failure, cancellation, or closing the last extension panel disposes the cursor and annotations on all visited tabs and releases their debugger sessions. The panel's runtime connection provides close detection, and session storage retains visited-tab IDs across worker suspension. Keyboard actions with no focused control preserve the last cursor position instead of moving to the document edge. Click ripples and typing/scroll/drag cues expire; the badge returns to “Sloth” after inactivity. Keyboard input briefly marks the focused control. Legacy click/type/select/scroll/submit tools also show a cue. Decoration failures never block input. No input contents are included in cursor messages or labels.

Run `npm test` for the regression suite, and `npm run build` to package the extension. With Vite running, open `/tests/fixtures/guidance-preview.html` for a manual visual and keyboard fixture. It exercises the actual injected renderer, drawing variants, wrong clicks, Save followed by a visible confirmation, Escape, and timeout.
